## Workflow

1. **Idea.** The owner sends a feature idea to the coordinator.
2. **Plan.** The coordinator writes, in the main checkout, `docs/ai-eng/plans/<plan-id>.md` from `docs/ai-eng/plan-template.md`: tasks, the conductor that owns each task, interfaces, acceptance criteria, architecture, and which optional subagents each task needs.
3. **Owner edit.** The owner edits the plan until it fits, then sends it to review.
4. **Plan review.** Conductor B (Codex) reviews the plan and records the verdict:
   `ai-eng review record --kind plan --plan-id <plan-id> --verdict GO|NO-GO --reviewer codex --author coordinator --finding "..."`
   On NO-GO the coordinator revises the plan and asks for another review. After @@MAX_REVIEW_ROUNDS@@ NO-GO rounds, stop and escalate to the owner.
5. **Dispatch.** On GO, the coordinator sends each task to the conductor that owns it.
6. **Build.** The conductor creates a task branch from `@@BASE_BRANCH@@` (for example `claude/<plan-id>-<task>` or `codex/<plan-id>-<task>`) and works with its subagents (below).
7. **Commit.** When the task's acceptance criteria are met and `@@TEST_COMMAND@@` passes, the conductor commits.
8. **Commit review.** The *other* conductor reviews that exact commit (to run its tests: `git switch --detach <task-branch>` in the reviewer's own worktree, then switch back) and records the verdict:
   `ai-eng review record --kind commit --branch <task-branch> --verdict GO|NO-GO --reviewer <reviewer> --author <author> --test "<command>: <result>" --finding "..."`
   On NO-GO the author fixes, commits, and asks for another review. After @@MAX_REVIEW_ROUNDS@@ NO-GO rounds, stop and escalate to the owner.
9. **Publish.** When `ai-eng review check --branch <task-branch>` exits 0 (GO on the current head SHA), the author pushes the branch and opens a **draft** PR using the PR template.
10. **Merge.** Only the owner merges.

## Automated mode

`ai-eng run "<feature idea>"` runs this workflow for you, with every agent as an Orca worker. Run it from a terminal inside Orca, in the main checkout. The coordinator writes the plan and stops so the owner can edit it. `ai-eng run --continue <plan-id>` then does steps 4 to 9 with no hand-offs:

- Codex reviews the plan, and the coordinator revises it until GO.
- Claude's tasks and Codex's tasks are built in parallel, each in its owner's worktree with its subagents.
- ai-eng runs `@@TEST_COMMAND@@` itself and commits.
- The other conductor reviews that exact SHA in its review worktree (`review-claude` or `review-codex` next to the conductor worktrees); NO-GO loops back to the author.
- On GO, ai-eng pushes and opens a draft PR.

Agents never commit, push or open PRs in this mode; ai-eng does that after its own checks. If you were started by ai-eng as an Orca worker, do only the task you were given and end with the reply it asks for. ai-eng stops and asks the owner on escalation, on repeated test failures, or when an agent times out. `ai-eng run --status` shows progress.

## Rules

- **No self-review, ever.** The conductor that wrote a commit never reviews it. `ai-eng review record` refuses a review whose reviewer is the author.
- **A GO covers one SHA.** Any new commit needs a new review before push.
- **Reviewer unavailable means blocked.** Record the blocker with `ai-eng handoff --note "..."` and wait. Never substitute a self-review or a subagent's review.
- Never force-push, rewrite shared history, merge PRs, delete branches or worktrees, change repository settings, or touch secrets.
- Never put secrets, tokens or credentials in code, plans, reviews, PRs or handoffs.
- Usage limits: you may move subagent work to a lower tier. Switching models does not bypass subscription-wide limits. If you must stop, run `ai-eng handoff` so the branch, SHA, tests and blockers are saved.

## What is enforced and what is policy

- **Enforced for Claude Code** by `.claude/settings.json` deny rules: force push, hard reset, `gh pr merge`, reading `.env` files.
- **Enforced by GitHub** only if branch protection is turned on for `@@BASE_BRANCH@@`. Check with `ai-eng doctor --online`.
- **Policy only:** everything else, including all Codex behavior. These guardrails are best-effort, not a sandbox.

## Commands

| Command | What it does |
|---|---|
| `ai-eng run "<idea>"` / `--continue <plan-id>` / `--status` | Automated mode (above). |
| `ai-eng doctor` | Read-only health check: configured, verified, untested, missing, blocked. |
| `ai-eng review record` / `check` / `list` | Record and check GO/NO-GO verdicts tied to exact SHAs. |
| `ai-eng handoff` | Write a sanitized status handoff (branches, SHAs, reviews, blockers). |
| `ai-eng upgrade --plan` | Show template updates without applying them. |
